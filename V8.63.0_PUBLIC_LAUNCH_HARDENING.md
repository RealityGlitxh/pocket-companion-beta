# Pocket Companion V8.63.0 — Public Launch Hardening

## Added
- Dedicated `privacy.html`, `terms.html`, and `support.html` launch pages.
- In-app release-readiness status on About & Privacy.
- Support diagnostic report version corrected to V8.63.0 RC.
- Lightweight local runtime-error ring buffer (`PPCLaunch.getRuntimeErrors()`), capped at 20 entries. No automatic error upload.
- PWA/service-worker cache boundary moved to V8.63.0 and legal/support pages are included in the app shell.
- All local JavaScript and primary CSS cache query strings moved to `v=8630`.

## Privacy/security behavior
- Runtime errors stay local unless the user explicitly chooses to share diagnostics.
- No passwords, provider secrets, Nintendo/Pokémon credentials, cookies, or reusable auth tokens are requested by the new support flow.
- Legal/support copy clearly states independent third-party status and unofficial nature of competitive estimates.

## Public-launch blockers that remain external/manual
- Configure a permanent public support/contact destination.
- Obtain appropriate legal/privacy review for the final production jurisdiction/audience.
- Complete hosted HTTPS iPhone/Safari and Android/Chrome QA.
- Complete real two-account Team Ranked/auth/cloud-sync E2E testing.
- Finalize production domain and Supabase Auth redirect configuration.
- Review existing project-wide Supabase security-advisor warnings before broad public launch.

No Supabase migration is required for V8.63.0.
