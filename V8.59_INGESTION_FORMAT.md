# V8.59.1 Pocket Sync ingestion format

The staging pipeline accepts a JSON object containing any of these arrays: `collection`, `rank_history`, and `battle_history`.

Collection records should provide a canonical `card_id`, or a set code plus card number, and an owned quantity. Rank records require a numeric `rp`/`points` value and may include timestamp, tier, result, and RP change. Battle records require a result that normalizes to win/loss/tie and may include timestamp, deck/opponent names, turn order, rank before/after, and notes.

The pipeline previews every record before merge. Existing Collection quantities that disagree are conflicts rather than automatic overwrites. Existing Rank/Battle IDs are duplicates and are skipped. Invalid/unmappable records are not applied.

This format is intentionally source-agnostic. It is an internal Companion ingestion contract, not documentation for a private Pokémon TCG Pocket endpoint.
