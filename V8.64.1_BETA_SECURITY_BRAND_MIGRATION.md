# PocketNexus V8.64.1 — Beta Security + Brand Migration

## Changes
- Migrated user-facing product branding from Pocket Companion to PocketNexus.
- Updated PWA manifest, browser/app titles, entry branding, dialogs, legal/support/offline pages, streamer overlay, and product documentation.
- Added diagnostic sanitization before runtime errors are stored or exported.
- Redacts JWT-like strings and sensitive OAuth/auth query parameters including access_token, refresh_token, token, code, id_token, authorization_code, and client_secret-like values.
- Removes URL fragments and embedded URL credentials from captured diagnostic URLs.
- Runtime errors use a fresh V8.64.1 storage key so unsanitized V8.64.0 logs are not carried into new beta reports.
- Bumped service worker and static asset cache-busting to 8.64.1 / 8641.

## Deployment
Designed for the closed beta at https://beta.pocketnexus.app. Google OAuth continues to use the Supabase callback endpoint; the app redirect target is supplied by the current hosted origin.

## Validation
Static JavaScript syntax, local references, service-worker shell references, branding scan, and ZIP integrity are checked before release. Real hosted OAuth/device QA remains required.

## Hotfix 1 — Tournament Live Cache Reliability
- Tournament catalog now hydrates from a persistent local cache immediately.
- Live catalog refresh is the primary request; filter/sync-status RPC failures no longer discard a successful catalog response.
- Failed refreshes preserve cached tournament data instead of dropping to the bundled snapshot.
- Search, participant, and format filters can run against cached catalog data while live refresh is unavailable.
- Tournament status now distinguishes LIVE CATALOG, CACHED, REFRESHING, and FALLBACK, with a useful last-synced time.


## Hotfix 2 — Combined Competitive Meta + Matchup Matrix
- Replaced the single-event Meta Center read with one combined competitive sample.
- Aggregates current competitive event records with imported tournament deck and match data.
- Default 30-day tournament window with 7/14/30/60/90-day controls.
- Added List and Matrix views; Matrix cells show observed win rate plus matchup game count.
- Added deck-entry count, mapped archetype count, and combined game-side sample size.
- No provider/source branding is exposed in the combined Meta Center panel.
- Production RPCs: `get_combined_competitive_meta` and `get_combined_matchup_matrix`.
- Current 30-day backend validation produced over 40,000 mapped game-side records, substantially increasing the sample beyond the original single-event panel.


## Hotfix 3 — Tournament crash recovery + update window + Training Lab polish
- Fixed an empty-standings retry loop that could repeatedly re-request the same tournament and destabilize the page.
- Tournament catalog RPCs now have a direct REST fallback when the shared Supabase client path fails.
- Tournament rendering has a recovery boundary so a display exception does not take down the full app.
- What's New is now an onboarding-style modal window and reflects the current PocketNexus beta release.
- Daily Training and Competitive Brain Teasers received a visual hierarchy and interaction polish pass.


V8.64.1 Hotfix 4 — Competitive Training Compact Layout
- Competitive Training now shows one scenario at a time instead of rendering all 19 vertically.
- Previous/Next controls and a complete scenario selector preserve access to every scenario and mode.
- Hero, mode chips, choices, explanation, progress, and reset remain available in a much shorter page footprint.

## Hotfix 5 — Public Grind Session Posts
- Completed Battle sessions can be posted to the signed-in player's public profile.
- Public session cards show deck, archetype, W-L(-T), win rate, total matches, grind duration, date, and RP change when available.
- Session posts are opt-in. Players can update or remove a posted session from Battle > Sessions.
- Match notes, opponent names, and per-match details are not included in the public post.
- Added `profile_session_posts` with owner-only RLS and `get_public_session_posts()` for public-profile-safe reads.
