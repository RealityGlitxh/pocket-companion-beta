# PocketNexus V8.64.1 Release Candidate QA

## Release gates
- Tournament page cannot take down the app when catalog, metadata, or standings requests fail.
- Cached catalog/standings remain usable during temporary sync failures.
- Tournament UI is source-neutral and contains no internal collector explanation.
- Combined Meta supports 7/14/30/60/90-day windows, List/Matrix views, and low-sample matchup labeling.
- Public profiles always render a Recent Grinds section; posted sessions show deck, record, win rate, duration, games, date, and RP change when available.
- Session posting remains opt-in and can be updated/removed by the owner.
- Google OAuth redirect resolves to https://beta.pocketnexus.app/ on the beta domain and auth-return credentials/codes are removed from the visible URL after successful session hydration.
- What's New uses a modal/onboarding presentation rather than an inline page.
- Training keeps all 19 scenarios while showing one scenario at a time.
- User-facing release surfaces use PocketNexus naming and avoid internal version/source implementation language.
- All JavaScript and service-worker syntax checks pass.
- Local HTML/JS/CSS references and manifest parse successfully.
- ZIP integrity passes before deployment.

## Hosted checks still required after deployment
- Google sign-in, sign-out, refresh persistence, and redirect return on beta.pocketnexus.app.
- Tournament catalog + event switch + empty standings recovery in a real browser.
- Meta Matrix horizontal scroll and sticky labels on a phone-sized viewport.
- Public session post/update/remove with two signed-in test accounts.
- PWA warm-cache/offline behavior and service-worker update adoption.
